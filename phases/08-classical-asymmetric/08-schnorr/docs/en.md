## The Problem
You want a compact, fast digital signature: a public-key way to prove “the holder of this private key approved this exact message.” Signatures are everywhere: software update signing, package registries, API requests, blockchain transactions, and authentication.

Schnorr signatures are simple, elegant, and show up in modern designs (often in elliptic-curve form). But that simplicity hides a sharp edge: each signature needs a fresh per-signature nonce. If that nonce is reused (or even biased), the private key can be recovered with basic modular algebra.

This lesson implements a toy Schnorr signature scheme in a finite-field subgroup, then demonstrates the nonce-reuse break so you can recognize and prevent it in real systems.

## The Concept
We work in a cyclic group of prime order `q` generated by `g`. For a toy finite-field setting, we use a subgroup of `(Z/pZ)*` with:

- Prime `p`
- Prime `q` such that `q | (p-1)`
- Generator `g` with `g^q ≡ 1 (mod p)` and `g != 1`

Keys:
- Private key `x ∈ {1, …, q-1}`
- Public key `y = g^x (mod p)`

Sign (one common Schnorr variant):
- Choose nonce `k ∈ {1, …, q-1}`
- `r = g^k (mod p)`
- `e = H(m || r) mod q`  (challenge)
- `s = k + e·x (mod q)`  (response)

Verify:
- Reconstruct `r' = g^s · y^{-e} (mod p)`
- Recompute `e' = H(m || r') mod q`
- Accept iff `e' == e`

The nonce reuse failure is immediate from the signing equation: if two signatures reuse the same `k`, then `s1 - s2 = (e1 - e2)·x (mod q)` and you can solve for `x`.

## Build It

### Step 1: Choose parameters and helpers
```python
import hashlib
import hmac


def int_to_bytes(x: int, length: int) -> bytes:
    if x < 0:
        raise ValueError("x must be >= 0")
    return x.to_bytes(length, "big")


def bytes_to_int(b: bytes) -> int:
    return int.from_bytes(b, "big")


def mod_inv(a: int, modulus: int) -> int:
    a %= modulus
    if a == 0:
        raise ValueError("inverse does not exist")

    t, new_t = 0, 1
    r, new_r = modulus, a
    while new_r != 0:
        q = r // new_r
        t, new_t = new_t, t - q * new_t
        r, new_r = new_r, r - q * new_r

    if r != 1:
        raise ValueError("inverse does not exist")
    return t % modulus


def bits2int(b: bytes, qlen: int) -> int:
    x = bytes_to_int(b)
    blen = 8 * len(b)
    if blen > qlen:
        x >>= blen - qlen
    return x


def hash_to_int(message: bytes, q: int, hashfunc=hashlib.sha256) -> int:
    return bits2int(hashfunc(message).digest(), q.bit_length()) % q


def int2octets(x: int, rolen: int) -> bytes:
    return int_to_bytes(x, rolen)


def bits2octets(h1: bytes, q: int, qlen: int, rolen: int) -> bytes:
    z1 = bits2int(h1, qlen)
    z2 = z1 % q
    return int2octets(z2, rolen)


def rfc6979_generate_k(x: int, h1: bytes, q: int, hashfunc=hashlib.sha256) -> int:
    qlen = q.bit_length()
    holen = hashfunc().digest_size
    rolen = (qlen + 7) // 8

    bx = int2octets(x % q, rolen) + bits2octets(h1, q, qlen, rolen)
    v = b"\x01" * holen
    k = b"\x00" * holen

    k = hmac.new(k, v + b"\x00" + bx, hashfunc).digest()
    v = hmac.new(k, v, hashfunc).digest()
    k = hmac.new(k, v + b"\x01" + bx, hashfunc).digest()
    v = hmac.new(k, v, hashfunc).digest()

    while True:
        t = b""
        while len(t) < rolen:
            v = hmac.new(k, v, hashfunc).digest()
            t += v

        candidate = bits2int(t, qlen)
        if 1 <= candidate < q:
            return candidate

        k = hmac.new(k, v + b"\x00", hashfunc).digest()
        v = hmac.new(k, v, hashfunc).digest()


def validate_schnorr_params(p: int, q: int, g: int) -> None:
    if p <= 2:
        raise ValueError("p must be > 2")
    if q <= 2:
        raise ValueError("q must be > 2")
    if (p - 1) % q != 0:
        raise ValueError("q must divide p-1")
    if not (2 <= g <= p - 2):
        raise ValueError("g out of range")
    if pow(g, q, p) != 1:
        raise ValueError("g^q mod p must be 1 (g not in subgroup of order q)")
```
Schnorr needs clean modular arithmetic and a stable hash-to-integer mapping. For a deterministic demo (no RNG dependency), we also implement an RFC 6979-style `k` generator using only `hashlib` and `hmac`.

### Step 2: Key generation
```python
def schnorr_public_key(p: int, g: int, x: int) -> int:
    if x <= 0:
        raise ValueError("private key must be > 0")
    return pow(g, x, p)
```
The public key is just a group exponentiation: `y = g^x (mod p)`. In real deployments you do this over an elliptic curve, but the structure is the same: a secret scalar and a public group element.

### Step 3: Sign and verify
```python
def schnorr_challenge(message: bytes, r: int, p: int, q: int, hashfunc=hashlib.sha256) -> int:
    r_len = (p.bit_length() + 7) // 8
    return hash_to_int(message + int_to_bytes(r, r_len), q, hashfunc)


def schnorr_sign(
    message: bytes,
    p: int,
    q: int,
    g: int,
    x: int,
    *,
    k: int | None = None,
    hashfunc=hashlib.sha256,
) -> tuple[int, int]:
    validate_schnorr_params(p, q, g)
    if x <= 0:
        raise ValueError("private key must be > 0")

    if k is None:
        h1 = hashfunc(b"SCHNORR:" + message).digest()
        k = rfc6979_generate_k(x, h1, q, hashfunc)
    k %= q
    if k == 0:
        raise ValueError("k must be non-zero modulo q")

    r = pow(g, k, p)
    e = schnorr_challenge(message, r, p, q, hashfunc)
    s = (k + e * (x % q)) % q
    return e, s


def schnorr_verify(
    message: bytes,
    p: int,
    q: int,
    g: int,
    y: int,
    signature: tuple[int, int],
    *,
    hashfunc=hashlib.sha256,
) -> bool:
    try:
        validate_schnorr_params(p, q, g)
    except ValueError:
        return False

    e, s = signature
    if not (0 <= e < q and 0 <= s < q):
        return False
    if not (1 <= y <= p - 1):
        return False

    y_inv = mod_inv(y, p)
    r = (pow(g, s, p) * pow(y_inv, e, p)) % p
    e2 = schnorr_challenge(message, r, p, q, hashfunc)
    return e2 == e
```
The signature is `(e, s)`: the verifier recomputes `r` from `s` and the public key, then checks that hashing it gives the same challenge `e`. We domain-separate the nonce derivation with a `"SCHNORR:"` prefix to avoid accidental cross-protocol reuse.

### Step 4: Nonce reuse leaks the private key
```python
def recover_x_from_nonce_reuse(
    q: int,
    e1: int,
    s1: int,
    e2: int,
    s2: int,
) -> int:
    de = (e1 - e2) % q
    if de == 0:
        raise ValueError("e1 must differ from e2 (mod q)")
    ds = (s1 - s2) % q
    return (ds * mod_inv(de, q)) % q
```
If the same nonce `k` is used for two different messages, the two `s` values differ only by `(e1 - e2)·x`, so you can solve for `x` with one modular inverse. This is why modern implementations strongly prefer deterministic nonces (or hardened RNGs) and strict domain separation.

## Use It
- **Ed25519 / EdDSA** (libsodium, OpenSSH, many runtimes): Schnorr-like signatures on an Edwards curve with deterministic nonces and strict encoding rules.
- **BIP340 Schnorr (secp256k1)** (Bitcoin/Taproot, libsecp256k1): Schnorr signatures with carefully specified hashing, nonce derivation, and key tweaks.
- **Production guidance:** do not implement signatures yourself. Use a mature library and follow the protocol’s exact spec (hashing, encoding, domain separation, subgroup checks).

## Pitfalls
- **Nonce reuse or bias:** reusing `k` can leak the private key. “Mostly random” nonces can be just as bad.
- **Missing domain separation:** using the same deterministic-nonce derivation across protocols can create cross-protocol attacks.
- **No group membership checks:** accepting public keys or points not in the right subgroup can break proofs and enable forgeries in some settings.
- **Ambiguous encodings:** if `H(m || r)` is not unambiguous (variable-length integers, missing length tags), different messages can hash to the same byte stream.
- **Toy parameters in real code:** small `p, q` make discrete logs easy. Real systems use large primes or elliptic curves with audited parameters.

## Key Terms
| Term | What people say | What it actually means |
|------|------------------|------------------------|
| Cyclic group | “A group generated by one element” | Every element is `g^k` for some `k` modulo the group order |
| Generator `g` | “A base point/base element” | An element that produces the whole subgroup when exponentiated |
| Nonce `k` | “Random per-signature value” | A secret ephemeral scalar; if reused/bias leaks, the private key can leak |
| Challenge `e` | “Hash challenge” | A hash-derived scalar binding the message (and commitment) into the signature |
| Response `s` | “The signature scalar” | The value that lets the verifier reconstruct the commitment `r` |
