# Cyclic Groups & Generators

> A cyclic group is a whole algebraic world reached by repeating one move.

## Learning Objectives

- Explain what makes a group cyclic and why a generator's order determines the size of the subgroup it spans
- Compute the generated subgroup `<g>` for elements in both additive `Z/nZ` and multiplicative `(Z/pZ)*` groups
- Identify all generators of a finite cyclic group and distinguish primitive roots from non-generators
- Apply the brute-force discrete logarithm to demonstrate why small generator order makes secrets trivially recoverable
- Verify generator validity by confirming that the generated subgroup covers the entire intended group

## The Problem

Groups tell you when an operation is well behaved. Cyclic groups tell you when one element can walk through the whole group by repetition.

That one idea sits directly under Diffie-Hellman, DSA-style signatures, Schnorr protocols, pairing-friendly curves, and many zero-knowledge systems. A protocol often publishes a generator `g`, then hides a secret exponent `x` inside `g^x`. If `g` really generates the intended large subgroup, the secret has room to hide. If `g` only cycles through a small set, the secret leaks.

Without cyclic groups, "choose a generator" sounds like a decorative setup step. With cyclic groups, it becomes a security boundary:

```text
Good:   g, g^2, g^3, ... reaches every element in a large subgroup
Bad:    h, h^2, h^3, ... reaches only a tiny cycle
```

The point of this lesson is to make that cycle visible, measurable, and testable.

## The Concept

Take a group `G` and an element `g`.

Repeat `g` with the group operation:

```text
e, g, g^2, g^3, ...
```

The set of all values you can reach is the subgroup generated by `g`, written `<g>`.

If `<g> = G`, then `g` is a generator and `G` is cyclic.

### Additive example

In `Z/6Z` under addition, the identity is `0`, and "powers" become repeated sums:

```text
<2> = 0, 2, 4
```

The element `2` does not generate all of `Z/6Z`; it gets stuck in a cycle of length `3`.

The element `5` does:

```text
<5> = 0, 5, 4, 3, 2, 1
```

So `5` is a generator of `Z/6Z` under addition. The element `1` is also a generator:

```text
<1> = 0, 1, 2, 3, 4, 5
```

For additive `Z/nZ`, the generators are exactly the residues coprime to `n`.

### Multiplicative example

For a prime `p`, the nonzero residues form the multiplicative group `(Z/pZ)^*`.

Modulo `7`, the elements are:

```text
1, 2, 3, 4, 5, 6
```

Try `3`:

```text
3^0 = 1
3^1 = 3
3^2 = 2
3^3 = 6
3^4 = 4
3^5 = 5
3^6 = 1
```

That cycle visits every nonzero residue before returning to `1`, so `3` is a generator of `(Z/7Z)^*`.

Try `2`:

```text
2^0 = 1
2^1 = 2
2^2 = 4
2^3 = 1
```

The element `2` has order `3`, not `6`, so it is not a generator.

### Why generators matter in crypto

Diffie-Hellman does not just need a group. It needs a group or subgroup where the chosen generator has large order.

```text
public parameters: group G, generator g
Alice secret:      a
Alice public key:  g^a
```

If `g` has order `q`, then only `q` possible public values exist. A small `q` means brute force is easy. A large prime `q` makes generic attacks expensive.

This is why serious protocols specify exact groups, exact subgroup orders, and validation rules. The generator is not decoration. It defines the cycle where secrets live.

## Build It

This lesson builds tools for finite cyclic groups:

- generate the subgroup `<g>`
- test whether an element is a generator
- list every generator
- find primitive roots modulo a prime
- brute-force a tiny discrete logarithm to see why small cycles are unsafe

### Step 1: Reuse modular group helpers

Use all residues for additive groups:

```python
def residues_mod(n: int) -> list[int]:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return list(range(n))
```

Use only units for multiplicative groups:

```python
from math import gcd


def units_mod(n: int) -> list[int]:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return [a for a in range(n) if gcd(a, n) == 1]
```

The operations are the same ones from the previous lesson:

```python
def add_mod(a: int, b: int, n: int) -> int:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return (a + b) % n


def mul_mod(a: int, b: int, n: int) -> int:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return (a * b) % n
```

### Step 2: Repeat one element

For a generic group, "exponentiation" means repeated use of the operation.

```python
def repeat_operation(element, exponent, identity, operation):
    if exponent < 0:
        raise ValueError("exponent must be non-negative")

    result = identity
    base = element
    power = exponent

    while power > 0:
        if power % 2 == 1:
            result = operation(result, base)
        base = operation(base, base)
        power //= 2

    return result
```

For addition, this computes repeated addition. For multiplication, this computes ordinary modular exponentiation. The algorithm is square-and-multiply written for any group operation.

### Step 3: Measure element order

An element's order is the first positive repeat that returns to the identity:

```python
def element_order(element, elements, operation):
    if element not in set(elements):
        raise ValueError("element must be in the group")
    if not is_group(elements, operation):
        raise ValueError("elements and operation must form a group")

    identity = find_identity(elements, operation)
    current = identity

    for order in range(1, len(elements) + 1):
        current = operation(current, element)
        if current == identity:
            return order

    raise ValueError("element order not found")
```

In a finite group, this search is bounded by the group size. Later you will prove stronger facts with Lagrange's theorem.

### Step 4: Generate `<g>`

The generated subgroup starts at the identity and walks by repeated `g`:

```python
def generated_subgroup(element, elements, operation):
    if not is_group(elements, operation):
        raise ValueError("elements and operation must form a group")

    identity = find_identity(elements, operation)
    subgroup = [identity]
    current = identity

    for _ in range(element_order(element, elements, operation)):
        current = operation(current, element)
        if current != identity:
            subgroup.append(current)

    return subgroup
```

Examples:

```python
z6 = residues_mod(6)
z6_add = lambda a, b: add_mod(a, b, 6)

assert generated_subgroup(2, z6, z6_add) == [0, 2, 4]
assert generated_subgroup(5, z6, z6_add) == [0, 5, 4, 3, 2, 1]
```

### Step 5: Find generators

An element is a generator when its generated subgroup has the same size as the whole group:

```python
def is_generator(element, elements, operation):
    return len(generated_subgroup(element, elements, operation)) == len(elements)


def generators(elements, operation):
    if not is_group(elements, operation):
        raise ValueError("elements and operation must form a group")
    return [element for element in elements if is_generator(element, elements, operation)]
```

For `Z/6Z` under addition:

```python
assert generators(z6, z6_add) == [1, 5]
```

For `(Z/7Z)^*` under multiplication:

```python
u7 = units_mod(7)
u7_mul = lambda a, b: mul_mod(a, b, 7)

assert generators(u7, u7_mul) == [3, 5]
```

Those are the primitive roots modulo `7`.

### Step 6: Brute-force a tiny discrete log

If `target = g^x`, the discrete logarithm asks for `x`.

```python
def discrete_log_bruteforce(base, target, elements, operation):
    if not is_group(elements, operation):
        raise ValueError("elements and operation must form a group")

    identity = find_identity(elements, operation)
    current = identity

    for exponent in range(len(elements)):
        if current == target:
            return exponent
        current = operation(current, base)

    return None
```

In `(Z/7Z)^*`, `3^3 = 6`, so:

```python
assert discrete_log_bruteforce(3, 6, u7, u7_mul) == 3
```

This is intentionally tiny. It is here to show the shape of the attack, not to solve real discrete logs.

## Use It

Production cryptographic libraries usually expose generators through fixed parameter sets, not through a "search all generators" API.

Examples:

- Finite-field Diffie-Hellman standards specify primes, generator values, and subgroup sizes.
- Elliptic-curve libraries expose a canonical base point with known large prime order.
- Pairing libraries expose generator points for source groups `G1` and `G2`.

The production habit is to verify what the library promises:

```text
What group is this element in?
What is the subgroup order?
Is the public element validated?
Is the identity rejected when required?
Is cofactor clearing needed?
```

Our code exhaustively searches tiny groups. Real libraries use fixed audited groups and validation routines.

## Attack It

### Small generator, small secret space

Suppose a protocol uses `(Z/7Z)^*` but accidentally chooses `2` as its base:

```text
2^0 = 1
2^1 = 2
2^2 = 4
2^3 = 1
```

Only three public values can appear. If a secret exponent is used with this base, an attacker only learns it modulo `3`, but that can be enough when combined with other small-order probes.

### Brute force in the generated subgroup

The generic brute-force attack does not need to search the whole declared group. It searches the cycle generated by the base:

```text
e, g, g^2, g^3, ...
```

If that cycle is short, the attack is short. The defense is to operate in a group or subgroup with large prime order and to validate external elements before mixing them with secrets.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Cyclic group | "Generated by one element" | A group `G` where some `g` satisfies `<g> = G` |
| Generator | "The base" | An element whose repeats reach every element of the group |
| Generated subgroup | "All powers of g" | The set `<g> = {e, g, g^2, ...}` produced by repeating one element |
| Element order | "Cycle length" | The smallest positive repeat that returns the element to the identity |
| Primitive root | "Generator mod p" | A generator of the multiplicative group `(Z/pZ)^*` |
| Discrete logarithm | "Undo exponentiation" | Given `g` and `g^x`, recover `x` in the generated subgroup |
| Small subgroup | "Tiny cycle" | A subgroup with few elements, dangerous when secrets are exponentiated inside it |
