## Learning Objectives

- Explain Lagrange's theorem and why subgroup order must divide group order in every finite group
- Verify that a given subset is a subgroup by checking identity containment, closure, and inverses

## The Problem

The previous lesson measured the cycle generated by one element. That cycle was not just a list. It was a subgroup: a smaller group living inside a larger group.

Cryptography constantly works inside subgroups. Diffie-Hellman often uses a large prime-order subgroup of a larger finite group. Elliptic curves often have a group order `h * q`, where `q` is a large prime and `h` is a small cofactor. Pairing systems, signature schemes, and zero-knowledge protocols all depend on knowing which subgroup an element belongs to.

If you cannot reason about subgroups, you cannot answer basic security questions:

```text
What is the order of the public key's subgroup?
Can an attacker send a small-subgroup element?
Does this generator really cover the intended set?
Why must subgroup order divide group order?
```

This lesson builds the finite-group tools behind those questions.

## The Concept

A subgroup `H` of a group `G` is a subset that is itself a group under the same operation.

That means `H` must:

| Rule | In plain language |
|------|-------------------|
| Contain the identity | The do-nothing element stays inside `H` |
| Be closed | Combining two elements of `H` stays in `H` |
| Have inverses | Every element of `H` can be undone inside `H` |
| Reuse associativity | This comes from `G`; you do not re-prove it |

### Generated subgroups

Every element generates a subgroup:

```text
<g> = {e, g, g^2, g^3, ...}
```

In `Z/12Z` under addition:

```text
<3> = {0, 3, 6, 9}
```

It is closed under addition modulo `12`:

```text
3 + 9 = 0 mod 12
6 + 9 = 3 mod 12
```

It also contains inverses:

```text
inverse of 3 is 9
inverse of 6 is 6
inverse of 9 is 3
```

So `{0, 3, 6, 9}` is a subgroup of `Z/12Z`.

### Cosets

Take a subgroup `H` and shift it by a group element `g`.

For additive groups, a coset looks like:

```text
g + H = {g + h : h in H}
```

For multiplicative groups, it looks like:

```text
gH = {g * h : h in H}
```

With `G = Z/12Z` and `H = {0, 3, 6, 9}`:

```text
0 + H = {0, 3, 6, 9}
1 + H = {1, 4, 7, 10}
2 + H = {2, 5, 8, 11}
3 + H = {3, 6, 9, 0} = H again
```

The cosets are not random overlaps. They partition the group:

```text
Z/12Z:

{0, 3, 6, 9}     size 4
{1, 4, 7, 10}    size 4
{2, 5, 8, 11}    size 4
----------------
12 elements total
```

Every coset has exactly the same size as `H`. Two cosets are either identical or disjoint.

### Lagrange's theorem

Lagrange's theorem says:

```text
If H is a subgroup of finite group G, then |H| divides |G|.
```

The reason is the coset partition:

```text
|G| = number_of_cosets * |H|
```

The number of cosets is called the index of `H` in `G`, written `[G : H]`.

For `Z/12Z` and `H = {0, 3, 6, 9}`:

```text
|G| = 12
|H| = 4
[G : H] = 3

12 = 3 * 4
```

This is why element orders divide group order. The generated subgroup `<g>` has size `ord(g)`, and Lagrange says that subgroup size must divide `|G|`.

### Why this matters in crypto

If a group has order `h * q`, a protocol may intend secrets to live in a subgroup of order `q`.

```text
full group order:      h * q
large prime subgroup:  q
small cofactor:        h
```

An attacker who can feed you elements from the small subgroup may learn information about your secret modulo small factors. This is the core shape of small-subgroup attacks.

Subgroup checks and cofactor clearing exist because Lagrange's theorem is not just a theorem. It is a map of where secrets can accidentally go.

### Step 1: Keep the group helpers

Start with modular addition and multiplication:

```python
from math import gcd


def add_mod(a: int, b: int, n: int) -> int:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return (a + b) % n


def mul_mod(a: int, b: int, n: int) -> int:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return (a * b) % n


def residues_mod(n: int) -> list[int]:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return list(range(n))


def units_mod(n: int) -> list[int]:
    if n <= 0:
        raise ValueError("modulus must be positive")
    return [a for a in range(n) if gcd(a, n) == 1]
```

These give you two reliable finite-group families:

```text
Z/nZ under addition
(Z/nZ)^* under multiplication
```

### Step 2: Test subgroup membership

A subset is a subgroup when it lives inside the group, contains the identity, is closed, and has inverses.

```python
def is_subgroup(subset, elements, operation):
    if len(subset) == 0:
        return False
    if len(set(subset)) != len(subset):
        return False
    if not set(subset).issubset(set(elements)):
        return False
    if not is_group(elements, operation):
        return False

    identity = find_identity(elements, operation)
    if identity not in set(subset):
        return False
    if not is_closed(subset, operation):
        return False
    return all(inverse_of(element, subset, operation) is not None for element in subset)
```

Example:

```python
z12 = residues_mod(12)
z12_add = lambda a, b: add_mod(a, b, 12)

assert is_subgroup([0, 3, 6, 9], z12, z12_add)
assert not is_subgroup([0, 2, 3], z12, z12_add)
```

The set `[0, 2, 3]` contains the identity, but it is not closed:

```text
2 + 3 = 5 mod 12
```

and `5` is not in the subset.

### Step 3: Build cosets

Left cosets multiply or add the representative on the left:

```python
def left_coset(representative, subgroup, elements, operation):
    if representative not in set(elements):
        raise ValueError("representative must be in the group")
    if not is_subgroup(subgroup, elements, operation):
        raise ValueError("subset must be a subgroup")

    return unique_in_order([operation(representative, h) for h in subgroup])
```

Right cosets put the representative on the right:

```python
def right_coset(representative, subgroup, elements, operation):
    if representative not in set(elements):
        raise ValueError("representative must be in the group")
    if not is_subgroup(subgroup, elements, operation):
        raise ValueError("subset must be a subgroup")

    return unique_in_order([operation(h, representative) for h in subgroup])
```

In abelian groups, left and right cosets match. In non-abelian groups, they may differ. Later lessons will use that distinction for normal subgroups and quotient groups.

For now:

```python
h = [0, 3, 6, 9]

assert left_coset(1, h, z12, z12_add) == [1, 4, 7, 10]
assert right_coset(1, h, z12, z12_add) == [1, 4, 7, 10]
```

### Step 4: List distinct cosets

Many representatives produce the same coset. In the example, `0`, `3`, `6`, and `9` all produce `H`.

So store each coset by its set of elements:

```python
def left_cosets(subgroup, elements, operation):
    if not is_subgroup(subgroup, elements, operation):
        raise ValueError("subset must be a subgroup")

    cosets = []
    seen = set()
    for representative in elements:
        coset = left_coset(representative, subgroup, elements, operation)
        key = frozenset(coset)
        if key not in seen:
            cosets.append(coset)
            seen.add(key)
    return cosets
```

For `Z/12Z`:

```python
assert left_cosets(h, z12, z12_add) == [
    [0, 3, 6, 9],
    [1, 4, 7, 10],
    [2, 5, 8, 11],
]
```

### Step 5: Check the partition

Cosets of a subgroup must cover the whole group without overlap.

```python
def cosets_partition_group(cosets, elements):
    if not cosets:
        return False

    element_set = set(elements)
    covered = set()
    for coset in cosets:
        coset_set = set(coset)
        if len(coset_set) != len(coset):
            return False
        if not coset_set.issubset(element_set):
            return False
        if covered.intersection(coset_set):
            return False
        covered.update(coset_set)
    return covered == element_set
```

Now the proof of Lagrange is executable:

```python
cosets = left_cosets(h, z12, z12_add)

assert cosets_partition_group(cosets, z12)
assert len(z12) == len(cosets) * len(h)
```

### Step 6: Report Lagrange data

The subgroup index is the number of distinct cosets:

```python
def subgroup_index(subgroup, elements, operation):
    return len(left_cosets(subgroup, elements, operation))
```

Then the theorem check is direct:

```python
def lagrange_holds(subgroup, elements, operation):
    if not is_subgroup(subgroup, elements, operation):
        raise ValueError("subset must be a subgroup")
    return len(elements) % len(subgroup) == 0
```

Useful report:

```python
def lagrange_report(subgroup, elements, operation):
    cosets = left_cosets(subgroup, elements, operation)
    return {
        "group_order": len(elements),
        "subgroup_order": len(subgroup),
        "index": len(cosets),
        "left_cosets": cosets,
        "partitions_group": cosets_partition_group(cosets, elements),
        "lagrange_holds": lagrange_holds(subgroup, elements, operation),
    }
```

For the running example:

```python
assert lagrange_report(h, z12, z12_add)["index"] == 3
```

## Use It

Production libraries rarely expose a function named `left_cosets`. They expose safer element types and subgroup-specific operations.

Common patterns:

| System | Subgroup issue |
|--------|----------------|
| Finite-field Diffie-Hellman | Public values must be in the intended subgroup and not the identity |
| Elliptic-curve Diffie-Hellman | Points must be valid and subgroup-safe; cofactors matter |
| Pairing curves | `G1`, `G2`, and target groups have distinct subgroup checks |
| SNARK systems | Structured reference strings contain elements expected in exact groups |

The production habit is:

```text
Use named, audited parameter sets.
Reject invalid encodings.
Reject the identity when the protocol requires it.
Validate subgroup membership or clear the cofactor.
Track the subgroup order used for security estimates.
```

Our code exhaustively checks tiny finite groups. Real code relies on library validation and protocol proofs.

## Attack It

### Small-subgroup confinement

Suppose a secret exponent `x` is used with an attacker-chosen group element `a`.

If `a` lies in a subgroup of order `r`, then:

```text
a^x only depends on x mod r
```

When `r` is small, the attacker can brute-force the few possibilities and learn a congruence about `x`.

In a group whose order factors as:

```text
|G| = h * q
```

small factors of `h` can create small subgroups. Lagrange's theorem guarantees that subgroup orders divide the group order, so the factorization of `|G|` tells you what small subgroup sizes may exist.

The defense is not "hope the attacker sends a good element." The defense is validation:

```text
check element is valid
check element is in the intended subgroup
reject identity when required
clear cofactors when the protocol calls for it
```

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Subgroup | "A smaller group" | A subset that is itself a group under the same operation |
| Generated subgroup | "All powers of g" | The subgroup `<g>` formed by repeatedly applying one element |
| Coset | "A shifted subgroup" | A set `gH` or `Hg` created by combining every subgroup element with one representative |
| Left coset | "g times H" | The set `{g h : h in H}` |
| Right coset | "H times g" | The set `{h g : h in H}` |
| Index | "Number of cosets" | `[G : H]`, the number of distinct cosets of `H` in `G` |
| Lagrange's theorem | "Subgroup size divides group size" | For finite `G`, every subgroup order `|H|` divides `|G|` |
| Cofactor | "The leftover factor" | The ratio `|G| / q` when a protocol uses a subgroup of order `q` |
